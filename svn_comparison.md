# Git vs SVN — ответы на вопросы

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
В Git ветка — это просто легковесный указатель (файл размером 41 байт с хешем коммита), поэтому создание ветки происходит мгновенно локально. В SVN ветка представляет собой копирование каталога на центральном сервере, что требует сетевых операций и работает медленнее.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет. SVN — централизованная система контроля версий, где вся история и репозиторий хранятся на центральном сервере. Без связи с сервером команда `svn commit` не может создать новую ревизию. В Git же коммит фиксируется в локальном репозитории (`.git`), а отправка на сервер (`push`) выполняется отдельно.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
- Огромные бинарные файлы и монорепозитории, когда клонировать всю историю целиком на каждый компьютер нецелесообразно (в SVN можно скачать только одну подпапку).
- Жёсткий централизованный контроль доступа на уровне отдельных директорий внутри одного репозитория (часто встречается в банках и госсекторе).
- Поддержка старых (legacy) проектов, где вся инфраструктура и регламенты уже завязаны на SVN.
